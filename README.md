# Redaction Review Studio

文本脱敏审阅工作台：检测建议按 **待审 / 接受 / 拒绝 / 已应用** 四阶段管理，
决策按文档 revision 与检测器版本追溯，最终脱敏文本只从完整冻结集生成。

Run `npm install`, then `npm run dev` (API on :4174, UI on :4173).
`npm test` 运行服务端测试（12 个用例）。

## 模型

- 建议身份 = `规则ID#出现序号`（如 `email#1`）。检测器升级保留规则 id 时身份不变；
  规则新增/删除分别表现为「新增」/「消失」。
- 每次检测产生一个 **run**（绑定文档 revision + 检测器版本 + 检测时内容）。
- 重复检测从上一次分析复用仍匹配的人工决策：
  - 普通决策自动跟随检测器给出的新范围（范围轻微变化）；
  - 自定义范围会比对原覆盖文本，文本漂移/改动时不自动复用，标记
    `priorDecision(text_changed)`，回到待审；
  - 消失的建议以 `gone` 保留展示。
- 生命周期标记：`new` 新增 / `carried` 决策已复用 / `returning` 重现但无可用决策 / `gone` 消失。

## 并发与冻结

- 每条决策带独立 `revision`（CAS，`baseRevision: 0` 表示决策必须尚不存在）；
  两页面并发改同一条建议时，后写者收到 `revision_conflict` 并拿到当前值，
  不做最后写入覆盖。
- run 有整体 `setRevision`，每次决策变更递增。
- 批量提交逐条 CAS，允许**部分提交**：响应区分 `applied` 与 `errors`。
- 冻结接口对 `setRevision` 做整体 CAS，并校验文档 revision 未变；
  失败即不生成任何最终文本，杜绝「一半新一半旧」。
- 冻结后 run 拒绝一切决策变更；冻结记录含文档 revision、检测器版本、
  每项决策快照（含 revision）、应用范围与最终脱敏文本，可幂等取回。

## 前端

- 四阶段 Tab（快捷键 `1-4`）；列表中 `A` 接受、`R` 拒绝、`U/Z` 撤销未冻结决策、
  `J/K` 移动；待审页支持一键全部接受/拒绝（仍逐条 CAS、可部分成功）。
- 接受后可用「调整范围」改为自定义区间；文档在检测后被编辑时显示「检测已过期」并阻止冻结。
- 冻结成功后弹出最终文本面板，含完整追溯快照；已应用阶段展示每条实际生效的范围。
